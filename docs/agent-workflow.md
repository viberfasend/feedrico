# Agent workflow: worktrees, checks, handoffs

How coding agents (Vibe, Claude Code) work in this repository alongside the user's own
checkout. `AGENTS.md` at the root summarizes this for any agent that starts here.

## Layout

- The repo root checkout is the user's: they run `npm run tauri dev` there, which owns
  port 1420. Agents never edit, commit or run servers in the root checkout.
- Each agent works in a git worktree under `.claude/worktrees/<agent-name>`:
  `git worktree add .claude/worktrees/<agent-name> <branch>`. `.claude/worktrees/` is
  git-ignored and excluded from the root checkout's Vite watcher and dependency scan
  (`isAgentCheckout` in `vite.config.ts`), so a dev server never crawls another agent's
  half-finished code.
- In a worktree, run a UI dev server on a different port, `npx vite --port 1430`, and stop
  it afterwards. Never start anything on 1420.
- Rust on this machine needs `PATH=/snap/bin:$PATH` (snap install); an older rustc first
  on `PATH` breaks the edition-2024 workspace.

## Commits

- Conventional Commits 1.0.0, enforced by the commit-msg hook (`.githooks/`) and CI.
  One meaningful commit per step — GitHub merges by rebase, so every commit lands on
  `main` as written.
- End every commit message with a blank line, the `Generated by <agent>.` line and the
  `Co-Authored-By` trailer of the authoring agent. See `git log main` for the exact
  spellings (Vibe: `Generated by Mistral Vibe.` / `Mistral Vibe <noreply@mistral.ai>`;
  Claude: `Co-Authored-By: Claude … <noreply@anthropic.com>`).
- Run all checks from `CLAUDE.md` before every commit.
- Commit locally on the task branch. Push and open PRs only when the user asks.

## Handoffs

- At the end of a batch, write the handoff in the worktree root (`HANDOFF.md`: per issue
  the status and commit hashes, what was built, deviations from the brief and why, tests
  added and how each was proven red, open questions, the output of the final check run)
  and COMMIT it on the branch.
- Reason: untracked files in a worktree are not durable. On 2026-11-11 a finished branch
  (`feat/settings-and-a11y`) was merged by rebase and its worktree was reset to
  `origin/main`; the untracked `HANDOFF.md` was lost and only the session log under
  `~/.vibe/logs/session/` still had it.

## Memory and shared context

- Vibe keeps no memory store; its transcripts live machine-local under
  `~/.vibe/logs/session/unified/<id>/`, scoped by working directory. Claude Code keeps its
  own history. Neither is readable by the other agent.
- The repository is the shared memory. The one instruction file both CLIs load is
  `AGENTS.md` at the project root (Vibe discovers it from the root up the trust chain;
  Claude Code reads it natively). Keep agent-facing rules there or in `docs/` and link
  them from `AGENTS.md`; keep `CLAUDE.md` as the long-form guide.
- Shared skills go in `.agents/skills/` (the Agent Skills standard; both CLIs load it).
  `.claude/skills/` is Claude-only, `.vibe/skills/` is Vibe-only — Vibe can import from
  `.claude/` once, but does not read it at runtime.
