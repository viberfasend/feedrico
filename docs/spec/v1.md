# Feedrico v1 specification

Feedrico is a desktop RSS reader that keeps everything on the user's machine. There is no account, no backend, no sync service and no telemetry. All user state lives in one portable **Library** that can be copied to a USB stick, opened on a friend's machine and shown there exactly as it was at home.

Vocabulary follows [`GLOSSARY.md`](../../GLOSSARY.md). Architectural decisions live in [`docs/adr/`](../adr/).

## Priorities

1. **Performance.** The app must feel instant. Every budget below gets a benchmark from the start.
2. **Portability.** One Library, opened anywhere, identical data.
3. **Local only.** The app talks to feed and website hosts, and to nothing else unless the user explicitly asks.
4. **A reading experience with character.** A warm, editorial design built on a complete token-driven design system.

## Performance budgets

Measured with 300 Feeds and 50,000 Articles on mid-range hardware.

| Metric | Budget |
|---|---|
| Cold start to interactive | < 500 ms |
| Switching Article, Feed, Folder or Smart View | < 50 ms |
| Article list scrolling | 60 fps (virtualized list) |
| Keyboard `j`/`k` to next Article rendered | within one frame |
| Refreshing 300 Feeds | in the background, no UI jank, < 30 s on decent internet |
| Idle memory | < 150 MB |

All heavy work (fetching, parsing, sanitizing, database, image cache, Pruning, search indexing) runs in the Rust core, off the UI thread.

## Platforms and stack

- Linux, Windows, macOS.
- Tauri 2 with a Rust core and a Svelte 5 + TypeScript UI ([ADR 0003](../adr/0003-tauri-rust-core-svelte-ui.md)).
- Bundled fonts only, no CDN: a variable serif (Literata) and a variable sans (Inter), both open-licensed.
- English UI only in v1.
- Licence: GPL-3.0.

## The Library

[ADR 0001](../adr/0001-library-is-single-source-of-truth.md), [ADR 0002](../adr/0002-library-on-disk-format.md).

### On disk

A folder named `Feedrico Library/`:

- `library.json`: manifest with the format version and the Library's creation info
- `library.db`: SQLite database for all structured data (Feeds, Folders, Articles, Read and Starred state, settings, the full-text index)
- `media/`: cached images and favicons, named by a hash of their source URL (the sanitizer rewrites image sources before the download, so the name must be known up front)
- `.lock`: present while the Library is open (see below)

Rules:

- No absolute paths anywhere inside the Library.
- Works on FAT32 and exFAT: filenames are ASCII-safe, no file exceeds 4 GB in practice, and there is no reliance on symlinks or POSIX permissions.
- Database writes are transactional. Pulling the stick loses at most the last action.

### What lives in the Library (travels)

Feeds, Folders, Articles with their content, Read and Starred state, cached images and favicons, and settings: theme, density, reader typography, refresh interval, retention rules, image cache cap.

### What stays on the machine (does not travel)

Window size and position, the list of recent Libraries, and "start with OS".

### Single source of truth and locking

- Exactly one Library is open at a time. A Library is never merged with a copy of itself.
- Opening a Library writes `.lock` with the machine name and time. Closing removes it.
- If a stale lock is found: "This Library was last open on *friend-laptop* at 21:14 and wasn't closed cleanly. Open anyway?"
- "Export / back up Library" copies the folder somewhere else (for example from the stick back to the home machine).

### Finding a Library on startup

1. **Portable Mode**: if a `Feedrico Library/` folder sits next to the executable, open it (Linux AppImage and Windows portable `.exe`; macOS always uses the installed app).
2. Otherwise open the most recent Library from the machine-local recent list.
3. Otherwise show the welcome screen:
   - **Create new Library** (default location: OS app-data directory; "Choose location…" can put it on a stick right away)
   - **Open existing Library…**
   - After creating: **Import OPML** or **Add Feed** as the first step.

"Open Library…" and the recent list are always reachable from the menu and the command palette.

### Format versions

- `library.json` carries a format version. It is a compatibility contract between app versions.
- **Newer app, older Library:** ask "Upgrade this Library? Older versions of Feedrico won't open it afterwards." Back up `library.db` before migrating.
- **Older app, newer Library:** refuse with "This Library needs Feedrico X or newer." Never write to it.

## Feeds and Folders

- Supported formats: RSS 0.9x/1.0/2.0, Atom, JSON Feed.
- A Feed is identified by its feed URL. It sits in at most one Folder, or at the top level.
- Folders are one level deep.

### OPML import

- Import is additive. Feeds already in the Library (same URL) are skipped, and their Folder and Read state stay untouched. Feeds missing from the OPML are not removed.
- Nested outlines are flattened into their top-level Folder.
- A URL that appears more than once keeps its first occurrence.
- New Feeds land in the Folder named exactly as in the OPML, created if missing. There is no fuzzy matching: if you renamed "Tech" to "Technik", a re-import puts new "Tech" Feeds into a new "Tech" Folder.

### OPML export

Exports all Feeds with their Folders.

### Managing Feeds

- **Add Feed** by feed URL, or by website URL with autodiscovery (`<link rel="alternate">` and common paths).
- Rename a Feed or Folder, move a Feed between Folders or to the top level, delete a Folder (the confirmation asks whether its Feeds move to the top level or are unsubscribed with their Articles; moving is the default), unsubscribe.

## Fetching

- On app start, on an interval while the app is open (default 30 min, configurable), and manually on demand.
- No background process when the app is closed.
- Polite fetching: conditional requests (ETag / Last-Modified), a concurrency limit, a timeout per request, and an honest User-Agent naming Feedrico.
- **Broken Feeds** (HTTP error, timeout, invalid XML): show a subtle warning badge with the last error and the last successful fetch time, and back off retries: 30 min → 2 h → 12 h. Broken Feeds are never removed automatically.
- Images referenced by new Articles are downloaded during fetch (see Image cache), so the Library works offline.

## Articles

- An Article belongs to exactly one Feed. The same post in two Feeds is two Articles with independent state.
- **Article Date**: the publish date if present and plausible, otherwise the time Feedrico first saw the Article. Future dates are clamped to first-seen.
- **Edited** upstream (same identity, new content): update the content silently and keep Read and Starred state.
- **Dropped** from the feed XML: keep the Article until Pruning removes it.
- **Enclosures** (podcasts, video): shown as a link to open or download. No inline player in v1.

### Read state

- An Article becomes Read when it is opened in the reader.
- Toggle manually with `m`.
- "Mark all as read" for a Feed, a Folder or a Smart View.

### Starred

Toggle with `s`. Starred Articles are never pruned.

### Pruning

- Starred Articles: kept forever.
- Read, unstarred Articles: removed when older than 90 days (configurable).
- Unread Articles: removed when older than 1 year (configurable).
- Pruning removes the Article's cached images too.

## Image cache

- Images are downloaded eagerly when an Article is fetched.
- Any single image over 5 MB is skipped and stays a remote link. So does an evicted image: the reader shows a link to the original, which opens in the system browser.
- A total cap is configurable (default 1 GB). Past the cap, images of Read, unstarred Articles are evicted first, oldest first.
- Favicons are always cached.

## Content safety and privacy

- Feed HTML is untrusted. It is sanitized in the Rust core: no scripts, no inline event handlers, no forms, no `style` attributes that could break layout.
- Strict Content Security Policy in the webview.
- iframes (YouTube etc.) are replaced by a link card, for example "Video on youtube.com: open in browser".
- The reader serves images **only from the local cache**. Opening an Article causes no network request, so there's no read-time tracking.
- Links always open in the system browser.

## Reading experience

### Panes

Three panes:

1. **Sidebar**: Smart Views (All Unread, Starred, Today), then Folders and top-level Feeds, with unread counts and broken-Feed badges.
2. **Article list**: virtualized, newest first by default with a per-view toggle for oldest first, presented in the View's Layout (see Layouts).
3. **Reader**: the Feed's own content, sanitized, with an "Open in browser" button. In grid Layouts it slides in over the grid instead of taking a pane.

### Layouts

A **Layout** is how the Articles of a View are presented. See "View", "Layout" and "Lead Image" in the glossary.

| Layout | Shape | Reader |
|---|---|---|
| **List** | Rows with Feed, Article Date, title and excerpt | Beside the list (three panes) |
| **Cards** | Uniform grid; columns adapt to window width (minimum card width is a token); Lead Images cropped to 3:2 | Slides in from the right over the grid |
| **Magazine** | Repeating bands: 1 large, 2 medium, 4 small stories; the large slot takes the first Article in its band with a Lead Image | Slides in over the page |
| **Gallery** | Square image tiles | Slides in over the grid |

- **Per View:** each Feed, Folder and Smart View remembers its own Layout, stored in the Library. Views without a choice use the global default (List). Search results use the global default.
- **No automatic choice:** the app never guesses a Layout for a View.
- **Switching:** a segmented control in the Article list header; `v` cycles Layouts; also a command palette action.
- **Lead Image:** the feed's own thumbnail (MediaRSS `media:thumbnail`, image enclosure), otherwise the first image in the content. Article web pages are never fetched for an image (`og:image` may become an opt-in per Feed later).
- **Articles without a Lead Image:** a typographic card in Cards (larger title, longer excerpt, gossamer motif); text-only slots in Magazine; hidden in Gallery, with a note such as "12 Articles without images not shown".
- **Slide-over reader:** `Esc` closes it; `j`/`k` keep moving through Articles while it's open.
- **Keyboard in grids:** `j`/`k` move in reading order (row by row); arrow keys move spatially; `Enter` opens the reader.
- **Read rule unchanged:** an Article becomes Read when opened in the reader, never by being visible in a grid.
- **Density** (comfortable/compact) applies to every Layout: card size, gaps, tile size.
- **Performance:** every Layout meets the same budgets, so every Layout is virtualized. Fixed-height rows and bands make that possible; a masonry grid (varying heights) is ruled out for this reason.

### Smart Views

- **All Unread**: every unread Article.
- **Starred**: every Starred Article.
- **Today**: Articles whose Article Date falls after local midnight.

### Search

Full-text search across Article titles and content (SQLite FTS5), scoped to everything, a Folder or a Feed.

### Keyboard

| Key | Action |
|---|---|
| `j` / `k` | next / previous Article |
| `s` | toggle Starred |
| `m` | toggle Read |
| `o` | open in browser |
| `r` | refresh |
| `/` | search |
| `v` | cycle Layouts |
| `Enter` / `Esc` | open / close the slide-over reader (grid Layouts) |
| `F6` / `Shift+F6` | move between panes (sidebar → Article list → reader) |
| Ctrl/⌘ + K | command palette |
| Ctrl/⌘ + `,` | Settings |

The **command palette** fuzzy-matches Feeds and Folders to jump to, plus actions: refresh, import OPML, export OPML, add Feed, mark all as read, toggle theme, open settings, open Library.

### Reader typography (stored in the Library)

Font family (serif or sans), size, line width (default ~66ch) and line height.

## Design system

### Visual direction

Editorial and calm, inspired by the Altweibersommer (the warm late-summer weeks): amber and honey accents in light mode, dusk violet in dark mode, a refined serif for reading, and a subtle gossamer-thread motif in empty states and branding.

### Tokens

- Source of truth: W3C Design Tokens (DTCG) JSON.
- Three tiers:
  - **primitive**: raw palette, type scale, spacing scale, radii, shadows, durations
  - **semantic**: for example `color.surface.raised`, `color.text.muted`, `space.inset.md`
  - **component**: for example `articleList.row.height`
- Style Dictionary generates CSS custom properties and TypeScript types. UI code only references semantic and component tokens, never primitives.
- Themes (light, dark, follow OS) and density (comfortable, compact) are token sets swapped at runtime through a root attribute, without re-rendering.
- The token build fails if any text/background pair in either theme misses WCAG 2.2 AA contrast.

### Components

Own components on top of Bits UI headless primitives, styled entirely through tokens.

### Accessibility and motion

WCAG 2.2 AA in both themes, visible focus rings, full keyboard operation, and subtle transitions that respect `prefers-reduced-motion`.

## Network policy

Feedrico makes network requests only to:

- feed URLs and the websites they point to (feeds, autodiscovery, images, favicons)
- GitHub Releases, **only** when the user clicks "Check for updates"

There is no auto-update, no telemetry, no crash reporting and no font or script CDN.

## Distribution

- Linux: AppImage (works in Portable Mode), plus `.deb`.
- Windows: installer plus portable `.exe` (works in Portable Mode).
- macOS: `.app` / `.dmg`. Portable Mode isn't supported because Gatekeeper quarantines apps run from removable media.

## Out of scope for v1

- Sync or merging Libraries
- Full-text extraction (Readability) for excerpt-only Feeds; later a per-Feed toggle
- Embedded web view of the original page
- Inline audio and video player
- Nested Folders, tags
- A Feed/Folder overview dashboard as an alternative to the sidebar
- `og:image` lookup for Lead Images; automatic Layout suggestions
- Cross-Feed deduplication
- Marking Articles read by scrolling past them; later a setting
- A "Feed health" Smart View
- Notifications
- Languages other than English
